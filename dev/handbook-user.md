## 一、首页与价值主张

### 1. 顶部价值主张 + 引导 CTA
- **定位**：首页 hero 区
- **现状**：打开即列表，用户不知道这是什么、能干嘛
- **改法**：
  - 在筛选条上方加一行价值主张：「实习就业雷达 —— 汇聚公开渠道的实习与校招岗位，按方向、行业、城市筛选，一键记录投递、跟踪进度。」
  - 下方放两个大按钮：「找实习」「找校招」，点击把类型 Tab 切到对应值并滚动到列表
- **验收**：首屏能在 1 秒内读出产品定位，两个按钮点击后类型筛选生效

### 2. 类型 Tab 默认选中「实习」
- **定位**：类型 Tab（实习 / 校招 / 全部）
- **现状**：默认是「全部」，首屏混着校招
- **改法**：初始选中「实习」；URL 同步 `?type=intern`；切换 Tab 时写 URL
- **验收**：刷新页面后仍停留在「实习」Tab；分享链接能复原类型选择

### 3. 默认方向筛选改为「技术方向」
- **定位**：筛选条件初始化
- **现状**：默认「全部方向 · 全部行业 · 全部城市」，首屏出现焊工、幼儿教师、酒店礼宾员
- **改法**：默认 `direction_group = '技术方向'`；若该分组无数据，回退为「全部」
- **验收**：首屏 24 张卡片 100% 是技术类岗位；选「全部方向」能看到非技术岗

## 二、筛选与搜索

### 4. 方向 / 行业字段渲染修复
- **定位**：卡片字段渲染 + 后端数据
- **现状**：24 张卡片里至少 8 张方向和行业字段为空（只显示「实习 · 民企」）
- **改法**：
  - 后端确认 `/api/jobs` 每条都返回 `direction` / `industry`；空值返回 `null` 不要空字符串
  - 前端卡片：有值才渲染 tag，无值不占位
  - 方向字段缺失率 > 30% 时，前端在控制台 warn，但不阻塞
- **验收**：每张卡片方向/行业要么有值要么完全不出现，不留空白 tag

### 5. 搜索框
- **定位**：筛选条右侧
- **现状**：无搜索框
- **改法**：
  - 加 `input[role="search"]`，placeholder「搜索公司、岗位、关键词」
  - debounce 300ms 后请求，搜公司名 + 岗位名 + 方向 三列 `ILIKE`
  - 搜索词写入 URL `?q=xxx`，刷新/分享可复原
- **验收**：输入「后端」300ms 后列表过滤；刷新后搜索词保留

### 6. 企业性质筛选
- **定位**：筛选条第四项
- **现状**：无此筛选项，但卡片上有「民企 / 国企」标签
- **改法**：筛选项加「企业性质」（民企 / 国企 / 外企 / 上市公司 / 未标注）
- **验收**：选「国企」后列表只显示国企岗位

### 7. 筛选条件折叠
- **定位**：筛选条
- **现状**：3-4 个筛选卡片占满首屏
- **改法**：默认折叠成一行「筛选条件」按钮，点击展开；已选项以 chip 形式展示在按钮旁
- **验收**：首屏能直接看到岗位列表，筛选条高度不超过 60px

## 三、岗位卡片

### 8. 截止时间字段
- **定位**：卡片底部
- **现状**：只有「发布：X 天前」，没有截止时间
- **改法**：
  - 卡片右下角加「截止：11月30日」
  - 截止时间 ≤ 3 天 → 红色 + 「即将截止」标签
  - 截止时间为空 → 整行隐藏，不显示「无截止时间」
- **验收**：有截止时间的卡片显示该字段；无截止的卡片不出现占位文字

### 9. 发布时间口径统一与视觉分级
- **定位**：卡片发布时间
- **现状**：有的写「发布：X 天前」，有的写「入库于今天」，口径混乱
- **改法**：
  - 统一文案为「发布于 X」（有 `published_at` 时）或「入库于 X」（只有 `created_at` 时），二选一
  - 入库时间可放到 tooltip，不占卡片空间
  - 视觉分级：今天 / 1 天内 → 绿色「NEW」；2-7 天 → 默认色；> 14 天 → 灰色
- **验收**：所有卡片发布时间文案格式一致；30 天前的卡片文字明显弱化

### 10. 岗位标题层级提升
- **定位**：卡片标题区
- **现状**：公司名和岗位名视觉权重接近
- **改法**：岗位名加粗放大为主标题（font-weight 700 / 16px），公司名降为灰色副标题（14px / secondary color）
- **验收**：扫一眼列表能先看到岗位名，公司名是次要信息

### 11. 来源字段修正
- **定位**：卡片来源标签
- **现状**：全部写「应届生求职网专业频道」（频道页不是来源）
- **改法**：
  - 来源只保留两个有效值：`应届生求职网` / `国家大学生就业服务平台`
  - 若 `applyLink` 不含具体职位 ID（非 `/job-xxx` 形式），来源后加 `⚠` 标记，且该卡片不允许入库投递追踪表
- **验收**：来源字段只出现两个站的名称；非具体岗位的卡片不允许点投递

### 12. 公司 Logo 占位
- **定位**：卡片左侧 logo 区
- **现状**：渲染公司名首字「上」「南」「武」裸文字，像没加载完
- **改法**：
  - 无 logo 时，渲染 36×36 纯色圆角方块 + 首字，背景色用公司名 hash 取固定色
  - 不渲染裸文字
- **验收**：所有卡片 logo 位是带底色的方块，不是裸首字

### 13. 薪资文案
- **定位**：卡片薪资
- **现状**：大量「薪资未公开」
- **改法**：空值改为灰色「薪资面议」；有值显示结构化 `min-max unit`
- **验收**：卡片上不再出现「未公开」字样

## 四、投递与追踪

### 14. 投递按钮 = 写入记录 + 跳转
- **定位**：卡片「投递」按钮
- **现状**：疑似纯外链跳转，不记录
- **改法**：
  - 点击时同步 `window.open('', '_blank')` 拿窗口句柄
  - `POST /api/tracking` 成功后 `w.location.href = applyLink`
  - 失败时关闭空窗口并提示重试
- **验收**：点投递后投递追踪页能看到该条记录，同时打开岗位详情页

### 15. 投递状态在卡片上直接显示
- **定位**：卡片投递按钮
- **现状**：点投递后卡片无变化，需切到追踪页才看到
- **改法**：已投递的卡片，按钮变「✓ 已投递」灰色不可点，下方小字显示投递日期
- **验收**：投递后回到列表，该卡片状态立即更新

### 16. 收藏入口
- **定位**：卡片「收藏」按钮
- **现状**：可能缺失
- **改法**：确保每张卡片有 `[⭐ 收藏]` 按钮，点击即写 `device_applications` 表（status=saved）
- **验收**：点收藏后，投递追踪页「收藏」列出现该岗位

### 17. 投递追踪时间线
- **定位**：投递追踪页每条记录
- **现状**：只有「进行中 / 已结束」两个列表
- **改法**：每条记录加状态流转节点：收藏 → 待投递 → 已投递 → 面试 → Offer / 拒绝，节点可点击推进，每次推进写入 `statusHistory`
- **验收**：点击节点能推进状态，刷新后保留，时间线显示每次变更时间

### 18. 收藏持久化
- **定位**：收藏数据存储
- **现状**：说明里写保存在当前浏览器，但未确认
- **改法**：`device_id`（UUID 存 localStorage）+ 服务端 `device_applications` 表；首次加载把本地旧收藏迁移上去
- **验收**：刷新后收藏保留；换浏览器丢失（已知限制，提供 JSON 导出兜底）

### 19. 导出投递记录
- **定位**：投递追踪页
- **现状**：有按钮但格式未知
- **改法**：导出 CSV，列：公司 / 岗位 / 城市 / 方向 / 投递日期 / 状态
- **验收**：下载的 CSV 能用 Excel 打开，字段完整

## 五、列表与计数

### 20. 分页 / 加载更多
- **定位**：列表底部
- **现状**：显示 24/785 但没看到分页控件
- **改法**：改用 infinite scroll，到第 24、48… 条时自动请求下一页；加「回到顶部」按钮
- **验收**：滚动到底部自动加载下一批；能一键回顶

### 21. 计数器语义
- **定位**：列表顶部计数
- **现状**：「24 / 785 个岗位」语义不清
- **改法**：
  - 有筛选：「北京 · 技术方向」匹配 12 条，共 785 条
  - 无筛选：785 个岗位，已显示 24 条
- **验收**：用户能一眼分清"匹配数"和"总数"

## 六、空态与错误

### 22. 筛选空态
- **定位**：筛选结果为 0
- **现状**：大概率白屏
- **改法**：插画 + 「该方向暂无岗位，试试放宽城市？」+ 一键清空筛选按钮
- **验收**：筛选 0 结果时不白屏，有明确操作引导

### 23. 数据异常兜底
- **定位**：`/api/jobs` 返回 5xx 或空数组
- **现状**：白屏
- **改法**：红色提示框「岗位数据暂时无法加载，请稍后刷新」+ 手动重试按钮
- **验收**：后端 500 时页面不白屏，有提示

### 24. 404 页
- **定位**：未知路由
- **改法**：兜底页面，加「返回首页」按钮
- **验收**：访问 `/xxx` 不白屏

## 七、管理面板

### 25. 管理面板从首页剥离
- **定位**：数据采集 / 解析实验 / Prompt 版本 / 样本集导入
- **现状**：平铺在主页
- **改法**：移到独立路由 `/admin`，首页只留一个低调入口（或完全隐藏，靠 URL 访问）；加 token 保护
- **验收**：首页看不到管理面板内容；`/admin` 需 token

### 26. 采集额度提示
- **定位**：admin 页顶部
- **现状**：「每日限量」但不显示剩余
- **改法**：显示「今日剩余解析次数：X / 20」
- **验收**：admin 页能看到实时剩余额度

## 八、数据修正（后端）

### 27. 岗位去重
- **定位**：入库逻辑
- **现状**：「春秋航空 运营专员（实习）」出现 2 次
- **改法**：按「公司 + 岗位名」做唯一键，重复则更新而非新增
- **验收**：同一岗位在列表中只出现一次

### 28. 方向 / 行业分类修正
- **定位**：分类逻辑
- **现状**：「教育培训」误判大量存在；方向字段大量为空
- **改法**：
  - 分类优先级：源站原始字段 > 关键词映射表 > 留空（不硬填）
  - 行业标注来源字段 `industry_source`（source / rule / null）
  - 抽 30 条人工核对，准确率 ≥ 85%
- **验收**：「教育培训」误判显著下降；空值不算错误，错标才算

### 29. 城市多值拆分
- **定位**：数据层
- **现状**：「北京、武汉、浙江」作为字符串存储，筛选用 includes
- **改法**：读时生成 `cities` 数组；筛选用数组匹配；单城市岗位排序优先
- **验收**：选北京不再混入纯外地岗位；多城市卡片显示「多地（N）」

### 30. 发布 / 入库时间分离
- **定位**：数据字段
- **改法**：`published_at`（源站发布时间）与 `created_at`（入库时间）分开存，卡片优先显示 published_at
- **验收**：卡片不再用「入库于今天」冒充发布时间

## 九、视觉与 SEO

### 31. 字号与行高
- **定位**：全局
- **现状**：body 14px
- **改法**：body 15px，line-height 1.6
- **验收**：正文不费眼

### 32. H1 / H2 层级
- **定位**：页面标题
- **现状**：可能 H1/H2 同名或层级混乱
- **改法**：每页只一个 H1（产品名 + 当前页），区块标题用 H3
- **验收**：无重复 H1，层级清晰

### 33. favicon
- **定位**：`<head>`
- **现状**：无
- **改法**：加 `<link rel="icon">`，用纯 SVG 字母标
- **验收**：浏览器标签页有图标

### 34. meta description
- **定位**：`<head>`
- **现状**：可能缺失或过期
- **改法**：补 `<meta name="description" content="聚合实习与校招岗位，按方向行业城市筛选，一站管理投递进度。">`
- **验收**：分享链接时能显示摘要

## 十、移动端

### 35. 移动端适配
- **定位**：< 768px
- **现状**：☰ 菜单存在，卡片表现未知
- **改法**：
  - 筛选条折叠为「筛选」按钮 + 抽屉
  - 卡片单列，logo 缩小到 32px
  - 底部导航固定（探索 / 投递 / 我的）
  - 检查分页按钮在窄屏是否可点
- **验收**：Chrome DevTools 手机模式下，所有操作可完成，无横向滚动
